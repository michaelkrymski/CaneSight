# CS-025 Swift-to-policy replay integration

These are **synthetic**, credential-free replay packets generated by the actual
CS-016 Swift `TelemetryCore`, then passed through accepted Python protocol
validation, role-bound backend relay, Pi `CaptureAgeGate`, local policy and capped
**simulated** output. There is no socket, phone, ARKit capture, Pi, camera, motor,
GPIO or physical test. This does not satisfy real-phone CS-025 acceptance.

```powershell
python -m unittest discover -s tests/edge -p test_swift_policy.py -v
```

The committed data lets the seven tests run without Swift. Tests verify the
fixture's exact source/generator hashes before interpreting results. This is an
explicit edge test command; normal root CI does not discover the separate edge
root and does not recompile Swift. Shared publishing checks are separate.

To regenerate from exact locally available review objects:

```powershell
python tests/edge/swift_policy_fixture/generate.py
python -m unittest discover -s tests/edge -p test_swift_policy.py -v
```

Requires local Docker and the pinned official Swift 6.0.3 image. The generator
does not fetch Git objects or use a device/SSH connection. It exports unchanged
PR #64 commit `0433fc94af1a1e3edfe2d2bb28925cb3be6df1ee` source into a
temporary build workspace, verifying every file's SHA-256 from
`review-inputs.json`. The review source is not accepted by this QA change.
Container execution has network disabled; the source bind is read-only and all
build products are inside the container's temporary copy. No package source is
vendored into the repository. Strict concurrency and warnings-as-errors are on.
Generation fails if the fixture/generator sources change during the run.

`synthetic-wire.json` stores base64 of **original Swift transmission bytes**,
not packets rebuilt by Python. Its ordinary envelope has a documented synthetic
clock-probe and a source clock exactly 200ms ahead of the virtual Pi clock, with
zero drift. Those are test assumptions, not device calibration. The only token
supplied to Swift is a fixed fake constructor value that never leaves its grant;
no credential appears in generated wire packets or fixtures. Session IDs, boot
IDs, frames and distances here are public synthetic test values.

Each side contains a clock reply, ready heartbeat, two normal depth captures,
limited-tracking/null-depth capture and a later heartbeat. The tests:

- relay the matching Pi probe and Swift phone reply under actual accepted role
  and session bindings, then calibrate the final-consumer gate;
- require two fresh Swift depth observations before requesting simulated left,
  right or both channels for a center obstacle;
- preserve original source capture time and the conservative 500ms deadline;
- deliver limited tracking while a delayed simulated side pulse is still active,
  then verify cancellation/unknown and that later health cannot restore it;
- reject original capture delayed beyond 500ms, duplicate packets and a foreign
  source boot without admitting another pulse.

These tests exercise `TelemetryCore`, not the native actor/socket at runtime.
Compiling the package does not establish `TelemetryClient` runtime behavior.
They do not wire synchronous CS-017 cleanup hooks to CS-016's actor-isolated
methods, authenticate a physical source, exercise the phone host or test actual
network/receiver-thread scheduling. Existing separate TLS/WSS tests retain their
own scope. Real phone capture-clock bounds/drift, native lifecycle integration,
physical mount mapping, driver/power/kill prerequisites and measured physical
response remain required before CS-025 is Done. Never reinterpret these fixture
times as end-to-end measured latency or crossing permission.
